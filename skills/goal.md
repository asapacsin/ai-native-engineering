# /goal — outcome-led execution

**Objective:** deliver the user's observable outcome, not merely a finished agent turn. This is an orchestration skill, not a magic persistent loop or permission to expand scope.

1. **Resolve the outcome.** Infer the requested end state and inspect the repository's AGENTS.md, current branch/dirty state, canonical specs, open work, and relevant tests. Use targeted reads. Specify observable acceptance, required proof level (unit, integration, end-to-end, device, GPU, human), excluded scope and time/cost bounds. State assumptions; ask the owner only for genuinely missing high-impact authorization.
2. **Create authorized work.** Split the outcome into small, independently verifiable tasks with dependencies. For every autonomous task, draft a separate JSON contract modeled on examples/contract.json with matching task_id, acceptance, required executable gates, budgets, approved_paths/forbidden_paths and base_commit. Put the mutable registry under a gitignored .ai-native/ directory or outside the checkout; each autonomous work item needs a contract_path resolving from the registry directory. Use examples/work.json as a schema reference, NOT as a ready-to-run backlog. Preserve external requirements separately from executor contracts (examples/requirements.json). Never impersonate an independent approver or silently edit protected governance.
3. **Validate before execution.** From the shared harness root:
    python3 scripts/ai_native.py validate --contract /absolute/path/to/task.json
    python3 scripts/frontier.py check --registry /absolute/path/to/.ai-native/work.json
    python3 scripts/frontier.py next --registry /absolute/path/to/.ai-native/work.json
   On Windows use python instead of python3. Explicit approval/scope rules are in docs/ENFORCEMENT.md.
4. **Run the real loop.** If real, authenticated, isolated Executor and read-only Reviewer commands are configured, favor the host-run supervisor:
    python3 scripts/supervisor.py --repo /absolute/path/to/target --registry /absolute/path/to/.ai-native/work.json --max-tasks 10 --max-seconds 1800
   Add --require-remote only if the task truly requires remote delivery and the trusted publication path is set up. For a single task, run scripts/ai_native.py cycle --repo ... --contract ... . Do not nest a CLI that launches another agent into itself without an intentional external host; when unavailable, execute allowed steps interactively and report independent review as NOT_VERIFIED.
5. **Prove each task, then re-check the full goal.** Follow /verify and /review-packet. Inspect latest evidence under .ai-native/runs/<task-id>/latest.json, ensure it matches source revision and contract hash, and use scripts/frontier.py next again. Only a verified eligible frontier item can be continued; route around independent external blockers. No source-provenance, gate or independent review means NO PASS. A code test PASS does not prove device/user-visible completion.
6. **End deliberately.** Report COMPLETE only when the agreed end state AND required independent requirements/release gates are verified, with no remaining authorized work and any required remote delivery. Otherwise report IN_PROGRESS, BLOCKED_EXTERNAL, HUMAN_REQUIRED, BOUND_REACHED or NOT_VERIFIED with evidence, what was not tested, and a specific next action. A bounded stop is legitimate; concealment of unfinished work is not.

**Runtime limitations:** Claude /goal is a discoverable skill; Codex uses $goal or skill selection. A skill cannot keep a Codex Cloud session alive or install an external runner. Claude Stop hooks are opt-in and advisory; the host-owned supervisor is the durable mechanism. Read docs/ENVIRONMENT_CONTINUATION.md and docs/HOOK_CYCLE.md before promising unattended execution. Never self-approve merges, change CI/branch rules unilaterally, leak credentials, or run an infinite recursive loop.
